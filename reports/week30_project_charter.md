## 1. 为什么还有一拳可打

W28 与 W29 已经把四个容量键逐个定价：

| 键 | 单键读数 | 谁测的 |
| --- | --- | --- |
| `max_depth` 2 → 4 | `+0.0137060796422638` → 0.5998203128630835 | W20-4 旁臂 / W28 阶梯 |
| `min_child_weight` 1 → 5 | `+0.0251306521711787` → 0.6249509650342622（5/5 种子过门，四键最大） | W20-4 旁臂 |
| `max_bin` 64 → 128 | 深度 4：`+0.0098462927268281` → 0.6096666055899116；深度 2：`+0.017053221078764724` → 0.6031674542995844 | W20-4 旁臂 / W29 |
| `colsample_bytree` 0.8 → 1.0 | `−0.0390331190248524`（深度 4）/ `−0.0478040823597`（深度 2） | W20-4 旁臂 / W29 |
| `reg_lambda` 1.0 → 0.1 | `−0.0795315855694289` | W29 |

W20-4 网格里的四个旁臂读数彼此只差 0.0033（0.599820 / 0.609667 / 0.621667 与 −0.039033 的 colsample），**在种子噪声内无法排序**；`reg_lambda` 只有「往小里调会掉」这一侧读数。因此单键方向已经定价完毕，剩下的是**组合**：

- `max_bin = 128` × `min_child_weight = 5` 在**深度 2** 上从未跑过（这两个键此前只在深度 4 上同动过）；
- 慢拟合路径（400 树 / lr 0.02）× `max_bin = 128` 从未跑过；
- 冠军配置上的 `reg_lambda` 只测过 0.1（往大里调到 200 从未跑过）。

## 2. 设计（跑前冻结）

固定档位阶梯，**不是搜索**：六个配置在同样的折上各拟合一次，没有任何选择器，外层测试行只被预测。六个档位里**前三档是复现锚**，用来确认整条代码路径与 W20-4 / W28 / W29 字节一致；**后三档是本轮的新组合点**。

| # | 档位 | 作用 |
| --- | --- | --- |
| 0 | `frozen_d2` | 复现锚：seed 42 = 0.6080587938801277，五种子端点 = 0.5861142332208197 |
| 1 | `w29_bin128_d2` | 复现锚：五种子端点 = 0.6031674542995844 |
| 2 | `w20_4_registered_d4` | 复现锚（跨周）：0.6216672295270079 |
| 3 | `bin128_mcw5_d2` | **新组合**：深度 2 + mcw 5 + bin 128 |
| 4 | `bin128_n400_lr02_d2` | **新组合**：慢路径 + bin 128 |
| 5 | `d4_mcw5_bin128_l200` | **新组合**：冠军 + `reg_lambda = 200` |

池、评分掩码、训练掩码、分组切分器、表示（`physical_lever4`，13 列稠密块）与五种子集合**逐字复用**冻结主记分牌；只覆盖六列声明键，`subsample` / `objective` / `tree_method` / `n_jobs` 一律不动。

## 4. 第二块：零成本的后验读数（不占 shot）

W29 §9 第 4 条要求「在新配置上重算排序口径，才能回答过门的是量级还是序」。落地时发现一件更省的事：W28 / W29 的逐重复表**本来就有** `spearman` / `auc_gt15` / `auc_gt30` 三列（`w28.METRIC_COLUMNS` 一直包含它们，被 `METRIC_NAMES` 排除的只是模块层那个七列冻结表头）。因此不需要重跑，就可以在**同一表示、同一折、同一种子集**上把「量级」与「序」拆成受控对照。
