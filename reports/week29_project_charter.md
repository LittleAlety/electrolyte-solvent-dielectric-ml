# Week 29 立项章：稠密块的分箱粒度与列采样（容量假设的最后一个未测维度）

- 触发：W28 的预注册把 `max_bin = 64` / `colsample_bytree = 0.8` / `reg_lambda = 1.0` 逐字列进 `frozen_keys_not_moved`，只移动 `max_depth` / `n_estimators` / `learning_rate`。**这三个键是同一类容量/正则化旋钮**，W28 没有测它们。
- 性质：**零新算力的固定档位阶梯 + 主记分牌一枪**。不跑 xTB、不装依赖、不联网。
- 机制依据：`max_bin = 64` 是当年为 **2048 列稀疏 Morgan 指纹**继承下来的；对 **13 列稠密浮点块**，每次分裂只在 **63 个候选阈值**里挑，这是分箱粒度上的欠拟合预算。`colsample_bytree = 0.8` 每棵树丢掉约 **3/13 列**；`reg_lambda = 1.0` 是在 457 行 / 97 化合物的稠密块上固定的叶惩罚。
- 主记分牌 shot：**1**（累计 16）。四个冻结读数（0.4091179943351143 / 0.4766400383507876 / 0.5861142332208197 / 0.6216672295270079）未动。

## 1. 为什么这是「阶梯」而不是「搜索」

W28 第 1 枪的嵌套选择在冒烟阶段就被记下一条负向证据：内层留出只有训练行的 1/3，R² 被少数极端 ε 化合物主导，三个外层折上内层 argmax 与折外 argmax **全部不一致**。因此 W29 **不再引入任何选择器**：六个固定配置在**完全相同的折**上各拟合一次，没有任何一步看过测试行（除了把它预测出来），每一档都是一个诚实读数。

这样做的代价是「不知道哪个配置会被自动选中」，收益是「每个配置的读数都是真的」。在容量假设已经接近天花板的时候，后者更值钱。

## 3. 口径纪律

- 池、评分掩码、训练掩码、分组切分器与五种子集合**逐字复用**冻结主记分牌（2391 行池、评分 457 行 / 97 化合物、训练掩码 full_base、5 折 × 10 重复、GroupKFold by InChIKey）。
- 表示是 W28 的 `physical_lever4`（13 列稠密块），**同一块、不做任何增删**。
- **锚**：seed 42 的冻结档位必须逐位复现 `0.6080587938801277`（容差 1e-9）；冻结档位的五种子端点必须复现 W28 的冻结臂 `0.5861142332208197`（容差 1e-6）。任一条不成立就不报任何结论。
- 折任务的 `random_state` 是固定常量 42（冻结折任务的定义），不是循环种子。
- **缺行不插补**、不丢弃评分行、不新增特征列。
- 图层级同句声明：本仓 = **GFN2-xTB / ddCOSMO 任意 ε / 刚性气相几何 / 242 分子**；母体论文 v6 = r2SCAN-3c / CPCM / 18 分子。

## 5. 三种可能的结局，以及每一种该写什么

1. **H29d 成立且 H29e 成立**：容量假设在分箱维度上被证实，冻结端点被抬过 0.60。必须同时报出这条档位是否**逐种子**稳健（H29f），以及它与 W28 两条枪、与 **W20-4 注册臂**的关系（见文末更正）。
2. **H29d 成立但 H29e 不成立**：分箱粒度确实是一个真实的小增益，但不足以过门。这是一个**正向但不足**的读数，按实测值报，不外推。
3. **H29d 判否**：容量假设在所有已测维度（深度、树数、学习率、分箱粒度、列采样、正则强度）上都被证否。此时「稠密块被超参惩罚」这条归因应当**整体撤回**，W27 的 0.0061 容量惩罚需要另找机制解释；这是本轮最有价值的一种结局，因为它把一整条假设线关掉。
