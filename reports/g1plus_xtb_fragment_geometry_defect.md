# 为什么 4 条 `model_ready=true` 的行进不了 236 行拟合集

日期：2026-09-25
范围：GFN2-xTB 物理特征生成步骤（`scripts/run_xtb_physical_features.py`）的缺陷诊断
结构化证据：`probes/g1plus_xtb_fragment_geometry_defect.json`
复现脚本：`probes/xtb_fragment_geometry_defect.py`（`--check` 校验已提交证据，`--check-cache` 用 git-ignored 缓存实测）
回归测试：`tests/test_xtb_fragment_geometry_defect.py`
状态：**本轮未改动任何冻结产物**（数据集、特征表、digest、交付包一律未动）

## 一、被记录了很久、但从未被解释的那 4 行

冻结 v0.3 名册声称 **240 行 `model_ready=true`**，但冻结拟合集只有 **236 行**。差额 4 行早已被记录为 `failed_physical_feature_count = 4`，
四个分子名也早就写在 `probes/dielectric_v03_representation_ablation_summary.json` 与
`probes/artifacts/v03_features_baseline_input.csv`（`status=error`）里。

**但没有任何产物说明它们"为什么"失败。** 四行都只带一句 `xTB failed ... with exit code 128`。本报告补上这一层诊断。

```
数据集 246 行
  ├─ model_ready = true   240
  │    ├─ 进入拟合集       236
  │    └─ 特征失败（本报告） 4   ← 全部 model_ready=true，却被静默挡在门外
  └─ model_ready = false    6
       ├─ 策展排除           5
       └─ 扣留（VC）         1
```

## 二、确认的缺陷：单次 ETKDG 嵌入把断开片段叠在一起

四个失败分子**全部是多片段物种**：三个是电荷分离的离子液体离子对，一个是六片段的金属羰基。
`generate_3d_xyz()` 对**整个不连通图**只调用一次 `EmbedMolecule`，RDKit 于是把各片段放在彼此身上。

判据是几何的、可复现的：取已提交的 xTB 起始几何（git-ignored 缓存 `data/interim/xtb_features/<InChIKey>/input.xyz`），
计算**跨片段**最短原子间距。

| 分子 | 片段数 | 现管线跨片段最短距离 | 该最近对是否跨片段 | <0.5 Å 的原子对 |
| --- | ---: | ---: | :---: | ---: |
| 1,3-二甲基咪唑鎓二甲基磷酸酯 | 2 | **0.163 Å** | 是 | 2 |
| 1-丁基-3-甲基咪唑鎓六氟磷酸盐 | 2 | **0.762 Å** | 是 | 0 |
| 1-丁基-2,3-二甲基咪唑鎓六氟磷酸盐 | 2 | **0.840 Å** | 是 | 0 |
| 五羰基铁 | 6 | **0.000 Å** | 是 | 20 |

这些距离低于分子图里任何一根化学键的键长（最短的 H–H 约 0.74 Å），而且最近对全部跨片段、在分子图里根本不成键——所以这四条起始几何都是不可接受的原子重叠，在物理上不可能存在。已记录到的 xTB 反应分成两类，逐字如下：

- 五羰基铁——直接拒绝几何：
  `-20- Found *very* short distance of  0.000E+00 for O8-O10`
  `-21- XTB REFUSES TO CONTINUE WITH THIS CALCULATION!`
- 三个离子液体——SCF 从坏几何出发无法收敛：
  `scf: Self consistent charge iterator did not converge`
  （第三个还叠了一层 `xtb_geoopt: Geometry optimization did not converge`）

也就是说：**四条失败都能追到同一段嵌入代码的几何缺陷，但复跑显示该缺陷被消除后四条仍全部 `exit 128`**——几何缺陷真实存在，且足以让 xTB 在五羰基铁上直接拒绝起始几何；但它不足以单独解释三个离子液体的 SCF 失败。

## 三、分离片段可以消除重叠，但**不能**单独救回这 4 行

探针实现了逐片段嵌入 + 按片段自身半径排布的打包：每个片段单独嵌入并力场预优化，居中后沿 +x 依次摆放，
相邻片段间隔至少 `padding`（实测用 3.0 Å）。

| 分子 | 现管线跨片段最短距离 | 打包后跨片段最短距离 |
| --- | ---: | ---: |
| 1,3-二甲基咪唑鎓二甲基磷酸酯 | 0.163 Å | **3.850 Å** |
| 1-丁基-3-甲基咪唑鎓六氟磷酸盐 | 0.762 Å | **4.328 Å** |
| 1-丁基-2,3-二甲基咪唑鎓六氟磷酸盐 | 0.840 Å | **4.136 Å** |
| 五羰基铁 | 0.000 Å | **3.000 Å** |

打包后每个分子里最近的一对原子重新变回**片段内的正常键**——重叠确已消除。

**但用这些几何重新跑 xTB，四条仍然 exit 128。** 这说明几何缺陷是真的、却不是唯一障碍，剩下两个残余问题性质不同：

1. **三个离子液体：SCF 策略问题。** 即便从合法几何出发，GFN2-xTB 对离子对仍不收敛。
   本轮只证明"几何修法不足以解锁"，尚未确定应采用哪种 SCF 策略（不同初猜、电子温度展宽、或 GFN-FF 预优化），因此不报告 HL-Gap 等数值。
2. **五羰基铁：结构表示问题，不是几何问题。** 库里存的 SMILES
   `[C]=O.[C]=O.[C]=O.[C]=O.[C]=O.[Fe]` 忠实转写自 `InChI=1S/5CO.Fe`，而这个 InChI **根本不表达 Fe–C 键**：
   它描述的是"5 个孤立 CO + 1 个自由铁原子"，不是 Fe(CO)₅。要修就得换一条能表达配位键的结构路径；
   实测并非所有写法都被拒绝：`O=C=[Fe](=C=O)(=C=O)(=C=O)=C=O` 能通过 RDKit 净化，却无法嵌入；`[Fe](C#O)...` 这类写法才触发价键检查（`Explicit valence for atom # 2 O, 3, is greater than permitted`）。所以单纯换 SMILES 不够，需要一条同时能通过净化与嵌入的结构路径。

## 四、这为什么值得记一笔

1. 它把一句不透明的 `exit code 128` 换成了可复现的几何判据，并区分开两个性质完全不同的残余问题。
2. 它指出了一个**潜在的、会继续发作的缺陷**：只要将来名册再加入任何多片段物种（离子液体、盐、多组分体系），
   同一段嵌入代码就会再次产出物理上不可能的起始几何。
3. 它给"能不能把这 4 行救回拟合集"这个后续问题划出了边界：**本轮尚不能判定"可以"**——几何修法只是必要条件，
   还缺一个能让离子对收敛的 SCF 策略，以及一条能同时通过净化与嵌入的 Fe–C 结构路径。三项都成立后，
   拟合集才可能从 236 变成 240，届时所有基准数字都会随之改变。这正是本轮不擅自落地的原因。

## 五、本轮没有做什么

- 没有改 `generate_3d_xyz()`。改它会改变多片段分子的特征值，令冻结的
  `data/processed/dielectric_physical_features_v03.csv` 与代码不再自洽；修法只以探针形式提供。
- 没有改任何数据集单元格、digest、排除单、交付包或论文草稿。
- 没有把这 4 行算进拟合集，也没有宣称它们的特征现在可用。

## 六、下一步（需明确授权才执行）

若要把这 4 行救回，建议作为**独立一轮 v0.3.14**，按项目既有纪律执行：

1. 在 `generate_3d_xyz()` 引入片段感知打包，并对多片段构型加几何健康检查（跨片段最短距离下限）；
2. 为离子对确定可复现的 SCF 策略，并把该策略写进特征 manifest；
3. 为五羰基铁换用能表达配位键的结构来源，或明确把它标为"结构不可用"；
4. 重跑 236 → 240 的全部基准、重钉所有 digest、重出 week7/week8 交付包，并更新本汇总与手册。
