### 基建与治理

#### W20-7 三层标签规范 + 每格 provenance（无依赖｜成本极低）
- **规范句**：一个通道的标签必须**同源同水平**；引入另一理论水平的值时必须先做跨水平标定并登记 `calibration_id`；**标定不过门则该列整列留空、只作 `reference_only`**；**ML 预测值永不入池**；**受限许可值永不入池**。

- **落地**：给注册表加 sidecar provenance —— `channel / role ∈ {primary_reference, calibrated_estimate, reference_only, feature_only} / reference_level / calibration_id / source_doi / locator_table_figure / access_class`。**现有词汇已在册**（`calibrated_estimate` / `reference_only` / `linear_2fold_v1`），本步是「统一散落的 role 列」，不是造新科学。

#### W20-8 漏斗 KPI 定板 + 封顶修订（成本：低）
- **KPI 三组**（挂 D6 排序键）：① **排序类**：AUC>15 / AUC>30、Spearman、top-k 富集；② **覆盖与成本类**：可评分化合物数、域内覆盖率、每候选算力与实验成本；③ **纪律类**：`promoted=false` 计数、主记分牌尝试数、placebo 塌缩、红线违规 0。
- **明令不做 R² KPI** —— 总诊断是「**排序学会了、量级学不会**」，R² 量的是量级。
- **命名纪律**：文献里的 **KPI = Knowledge-based electrolyte Property prediction Integration（框架名）**，与自家漏斗 KPI 指标**同名不同物** ⇒ 立项章只留一种用法。

### 6.3 结构性修正：让归档件永不自带占位符

根因**不是某个 DOI 写错**，而是 `README.md` / `release_notes_*.md` 里有一条 **「本版本 DOI：pending → 下个提交回填」** 的自引用行。归档发生在 tag 冻结的瞬间，而版本 DOI 只在发布后才存在 ⇒ **每一版归档件都必然带一句占位符或一句旧 DOI**。v1.1 与 v1.2 是同一根因的两次发作。

**建议**（W20 治理项，非本件动作）：归档可见的两个文件里，**本版本那一行改指 concept DOI**（`10.5281/zenodo.22957695`，版本无关、永远可解析）；**版本专属 DOI 只出现在 GitHub Release 正文与回填提交里**，而这两者不被 Zenodo 归档。这样归档件不再含任何可失效的自引用，回填提交也不再是「补一个已经归档的错」。
