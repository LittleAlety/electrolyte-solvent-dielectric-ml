## 0. 与 W20-4 的关系（先纠正一处容易混的口径）

W20-4 的**注册臂** `hp2_d4_n200_lr0.05_mcw5_ss0.8_cs0.8_bin128` 用的是**同一个 `physical_lever4` 表示、同一个池、同一套五种子口径**，也已经把端点推到 **0.6216672295270079（≥ 0.60）**。因此**「单表示端点第一次过 0.60」这件事发生在 W20，不是 W29**；W20-4 的臂名为「唯一晋升翼」，至今仍是本仓最高的注册读数。

W29 的贡献不是新纪录（0.6031674542995844 **低于** 0.6216672295270079），而是**深度 2 上的新配置点与交互读数**。这里要纠正一处容易混的口径：**不能说「W20-4 三键同动、无法归因」** —— W20-4 自己的预注册网格里本来就带逐键旁臂，**单键定价在 W20-4 就已经做完**：`min_child_weight` 1 → 5 单独 **+0.025131**（`0.6249509650342622`，5/5 种子过门，四键里最大）、`max_bin` 64 → 128 单独 **+0.009846**（`0.6096666055899116`，5/5 种子过门）、`max_depth` 2 → 4 单独 **+0.013706**（`0.5998203128630835`）、`colsample_bytree` 0.8 → 1.0 单独 **−0.039033**（`0.5607871938382311`）。注册臂把 mcw 与 bin 叠加后是 **0.6216672295270079**，**低于** mcw 单项（−0.003284），也低于可加性预测 `0.6347972577610903`（高估 0.0131）—— **键之间是负交互，不正交**。W27–W29 增加的是**新配置点（深度 2 + bin 128）**、**一条交互读数（分箱增益依深度从 +0.0171 降到 +0.0098）**、**一个未测键（`reg_lambda`）**与**一条方法论负结果（选择器偏好最差档位）**。

## 1. 本轮买到什么

W28 把容量假设在「深度 / 树数 / 学习率」三个维度上判否，但**逐字冻结了 `max_bin = 64` / `colsample_bytree = 0.8` / `reg_lambda = 1.0`**。W29 只移动这三个键，深度（2）、树数（200）、学习率（0.05）全部保持冻结档位，**没有任何选择器**：六个固定配置在同样的折上各拟合一次。

## 3. 四个必须并报的读数

1. **过门不是靠挑一个幸运档位。** 六个预注册档位里**有两档同时过门**（`fine_bin128_cs08_l1` = 0.6031674542995844、`fine_bin256_cs08_l1` = 0.6030335046064195），两档相邻、读数只差 **0.000134**（再加密反而略低）。**增益在 64 → 128 之间就已经饱和。**
2. **逐种子稳健性 4/5，掉的那一个种子很小。** 最佳档位逐种子对冻结档位：seed 42 **+0.011041573433676288**、1234 **+0.03458552717983865**、2026 **-0.0015022827723903953**、31337 **+0.010389224785914086**、7 **+0.030752062766784438**。唯一的负种子幅度 -0.0015 —— 不是翻转，是噪声。
3. **三个「容量键」方向相反，这才是本轮真正的产出。** `colsample_bytree` 0.8 → 1.0 掉 **-0.0478040823597**，`reg_lambda` 1.0 → 0.1 掉 **-0.0795315855694289**，三个键一起动掉 **-0.0818080462097462**。**列采样与叶惩罚不但不缺容量，反而在扛事。** 结合 W28（深度/树数/学习率的固定阶梯上限 0.599820、嵌套选择 -0.014899、Morgan 对照 +0.107182）：**「冻结超参一律对稠密块不合适」这条粗口径到此被拆成三个分别有答案的事实**，见下表。

| 维度 | 谁动过 | 读数 | 判决 |
| --- | --- | --- | --- |
| `max_depth` 2 → 4 | W20-4 旁臂（mcw 1、bin 64） | 单独 **+0.013706** → `0.5998203128630835` | **单独不足以过门**（差 0.000180） |
| `min_child_weight` 1 → 5 | W20-4 旁臂（d4、bin 64） | 单独 **+0.025131** → `0.6249509650342622`（5/5 种子过门） | **四键里最大的一项** |
| **`max_bin`** 64 → 128 | W20-4 旁臂（深度 4）/ **W29（深度 2 新配置）** | 深度 4：+0.009846 → `0.6096666055899116`；**深度 2：+0.017053 → `0.6031674542995844`** | **单独足以过门；增益依深度，几乎差一倍** |
| `colsample_bytree` 0.8 → 1.0 | W20-4 旁臂 / W29 | −0.039033（深度 4）/ **−0.047804**（深度 2） | **冻结值是对的，一动就掉** |
| `reg_lambda` 1.0 → 0.1 | W29（W20-4 未测） | **−0.079532** | **冻结值是对的，一动就掉** |
| 树数 / 学习率 | W28 阶梯 + W28/W20-4 嵌套重调 | 阶梯最佳 0.599820（含 d4）；嵌套 **−0.014899**；W20-4 内层折选择 0.610273 | **单独不足以过门；自动选择反着挑** |

4. **口径边界：这是新配置上的新读数，不是冻结读数的改写，也不是新纪录。** 四个冻结读数（0.4091179943351143 / 0.4766400383507876 / 0.5861142332208197 / 0.6216672295270079）**字节未动**；本轮的 0.6031674542995844 是**同一池、同一折、同一表示、同一五种子口径、但 `max_bin = 128` 且深度仍为 2** 的另一条读数，**永不与冻结读数混比**。它也**低于** W20-4 的 0.6216672295270079：W29 解释的是 W20-4 增益里的一部分来源，不是对它的超越。W27 已声明「Physical 单表示只作描述性次读数、不单独构成晋升路径」，本轮不改变该声明。

## 5. 不宣称（必须并报）

- **不宣称「首次过门」**：首次过门发生在 **W20-4**（同一池、同一表示、同一口径，0.6216672295270079，已晋升）。W29 是**深度 2 上的新配置点 + 交互读数**，不是新纪录。
- **不宣称「0.60 已达标」**：本轮的 0.603167 是在**单表示（Physical 13 列）**口径下、**固定档位**（不是自动选择）的读数，与冻结头条 0.4766400383507876（Morgan+Physical）**不是同一块记分牌**，不能互相替换。
- **不宣称「超参调好了」**：本轮增益只来自一个键（`max_bin`），另两个键（`colsample_bytree` / `reg_lambda`）一动就掉；这说明**冻结配置在列采样与叶惩罚上是对的**，不能推广成「随便调都行」。**也不宣称「`min_child_weight` 未定价」** —— 它在 W20-4 就有单独旁臂（1 → 5 单独 +0.025131，四键最大，5/5 种子过门）；到 W29 为止**四键都已有单独读数**，「未定价」不再是任何键的状态。
- **不宣称「排序/量级问题解决了」**：R² 过门只说明量级口径上了一个台阶，本仓既有的「排序学会了、量级学不会」结论需要在新配置上重算 AUC/Spearman 才能更新（既有 AUC 侧车不覆盖 `max_bin = 128`、深度 2 的这个组合）。
- **不外推**：本轮只在此名册、此池、此表示上成立；不宣称分箱粒度对别的表示（Morgan 稀疏块）也有同样的增益。
