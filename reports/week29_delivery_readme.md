## 1. 本轮买到什么

W28 把容量假设在「深度 / 树数 / 学习率」三个维度上证否，但**逐字冻结了 `max_bin = 64` / `colsample_bytree = 0.8` / `reg_lambda = 1.0`**。W29 只移动这三个键，深度（2）、树数（200）、学习率（0.05）全部保持冻结档位，**没有任何选择器**：六个固定配置在同样的折上各拟合一次。

结果：**六条判据全部成立**，而且这是本仓第一次把单表示端点推过 0.60：

| 档位 | 五种子均值 | 与冻结档位之差 |
| --- | --- | --- |
| frozen_bin64_cs08_l1（冻结档位） | 0.5861142332208197 | —— |
| **fine_bin128_cs08_l1（本轮最佳）** | **0.6031674542995844** | **+0.017053221078764724** |
| fine_bin256_cs08_l1 | 0.6030335046064195 | +0.01691927138559980 |
| full_cols_bin64_cs10_l1 | 0.5383101508611199 | -0.0478040823597 |
| loose_lambda_bin64_cs08_l01 | 0.5065826476513908 | -0.0795315855694289 |
| all_three_bin256_cs10_l01 | 0.5043061870110735 | -0.0818080462097462 |

**一句话：把分箱从 64 提到 128（或 256）就过门；把列采样放开、把叶惩罚放松都会掉分，三个一起动掉得最多。**

## 3. 四个必须并报的读数

1. **过门不是靠挑一个幸运档位。** 六个预注册档位里**有两档同时过门**（`fine_bin128_cs08_l1` = 0.603167、`fine_bin256_cs08_l1` = 0.603034），而且它们是相邻设置、读数几乎相同。增益在 64 → 128 之间就已经**饱和**：再加密到 256 只多 0.000134（反而略低）。
2. **逐种子稳健性 4/5，掉的那一个种子很小。** 最佳档位逐种子对冻结档位：seed 42 **+0.011041**、1234 **+0.034586**、2026 **-0.001502**、31337 **+0.010390**、7 **+0.030752**。唯一的负种子是 2026，幅度 -0.0015 —— 不是翻转，是噪声。
3. **两个「容量键」方向相反，这才是有信息量的部分。** `colsample_bytree` 从 0.8 放开到 1.0 掉 **-0.047804**，`reg_lambda` 从 1.0 放松到 0.1 掉 **-0.079532**，三个键一起动掉 **-0.081808**。也就是说：**冻结配置里真正欠拟合的只有分箱粒度；列采样与叶惩罚不但不缺容量，反而在扛事。** 这修正了「冻结超参一律对稠密块不合适」的粗口径——W28 证否了深度/树数/学习率那条，W29 证否了列采样/叶惩罚那条，只留下分箱这一条。
4. **口径边界：这是新配置上的新读数，不是冻结读数的改写。** 四个冻结读数（0.4091179943351143 / 0.4766400383507876 / 0.5861142332208197 / 0.6216672295270079）**字节未动**；本轮的 0.6031674542995844 是**同一池、同一折、同一表示、同一五种子口径、但 `max_bin = 128`** 的另一条读数，两者**永不混比**。W27 已声明「Physical 单表示只作描述性次读数、不单独构成晋升路径」，因此本轮的过门**不等于自动晋升**：晋升需要另行立项，把端点规则与晋升条件先写进预注册。

## 5. 不宣称（必须并报）

- **不宣称「0.60 已达标」**：本轮的 0.603167 是在**单表示（Physical 13 列）**口径下、**固定档位**（不是自动选择）的读数，与冻结头条 0.4766400383507876（Morgan+Physical）**不是同一块记分牌**，不能互相替换。
- **不宣称「超参调好了」**：增益来自一个键（`max_bin`），另外两个键一动就掉；这说明**冻结配置在列采样与叶惩罚上是对的**，不能推广成「随便调都行」。
- **不宣称「排序/量级问题解决了」**：R² 过门只说明量级口径上了一个台阶，本仓既有的「排序学会了、量级学不会」结论需要在新配置上重算 AUC/Spearman 才能更新（既有 AUC 侧车不覆盖 `max_bin = 128`）。
- **不外推**：本轮只在此名册、此池、此表示上成立；不宣称分箱粒度对别的表示（Morgan 稀疏块）也有同样的增益。
