## 二、抽取模板 v0 —— 字段清单

记录粒度：**一条记录 = 一个（化合物, 通道性质, 数值）观测行**。字段名即预注册 JSON 里的 key，逐字一致。

| # | 字段名（json key） | 类型 | 必填 | 缺失时行为 | 校验规则 |
| --- | --- | --- | --- | --- | --- |
| 1 | compound_name | string | 是 | 整条丢弃 | 去首尾空白后长度 ≥ 2；保留原文写法（不得顺手规范化成 IUPAC 名） |
| 2 | smiles | string | 是 | 整条丢弃 | RDKit `MolFromSmiles` 可解析；解析失败即丢弃，**不得人工替写结构** |
| 3 | inchikey | string | 是 | 由 SMILES 现算；算不出则整条丢弃 | 27 字符标准形（`XXXXXXXXXXXXXX-XXXXXXXXXX-N`）；须与 `smiles` 现算值**逐位一致** |
| 4 | disambiguation_confidence | float [0,1] | 是 | 整条丢弃（**不得默认 1.0**） | 名称 → 结构的消歧置信度；< 0.90 时整条进人工复核队列，不得直接入库 |
| 5 | property_value | float | 是 | 整条丢弃 | 有限实数；须过量级守卫（见 §五）；超界即人工复核 |
| 6 | unit | string（受控词表） | 是 | 整条丢弃 | 只收受控词表成员；原文非表内单位时，换算过程写入 `unit_note`，不得静默丢弃 |
| 7 | temperature_K | float | η / HOMO-LUMO / 氧化还原：是；ε：条件必填 | 整条丢弃 | 单位恒为 K；0 < T ≤ 1000；原文给 °C 时换算并留 `temperature_note` |
| 8 | method | string（受控词表） | 是 | 整条丢弃 | 只收受控词表成员；必须区分 reported 与 estimated（方法列不得合并口径） |
| 9 | source_doi | string | **是（硬门）** | **不入库** | 形如 `10.xxxx/...`；须可解析且对应一份仓库外合法来源 |
| 10 | locator_table_figure | string | **是（硬门）** | **不入库** | 形如 `Table 3 row 7` / `Figure 2b` / `page 5 Table S2`；无定位视为未核 |
| 11 | extraction_confidence | float [0,1] | 是 | 整条丢弃 | 抽取（非消歧）置信度；< 0.95 时整条进人工复核队列 |
| 12 | access_class | string（写入时自动） | 是 | - | `open_oa` 才可能入 `data/`；`restricted_crosscheck_only` 永不入 `data/`、永不入任何池（§七） |
| 13 | source_lane | string | 是 | 整条丢弃 | 取值 ∈ {eta, homo_lumo, redox, epsilon}，决定该行走 §三 的哪条通道门 |

分组读法：字段 1–4 服务**化合物消歧**；5–8 服务**数值字段**；9–10 是**硬门**；11 是**抽取置信度**；12–13 是治理列。

## 三、通道优先级与 ε 的条件性激活

先做顺序（逐条对应 §W19-2 原话「η、HOMO-LUMO、氧化还原先做」）：

1. **η（黏度）**——存量最大（42,941 数据行），且是当前离过门最近的在役通道（组键 MAE 0.174772 vs 门 0.15）。
2. **HOMO/LUMO**——已有基线池，文献值可直接做组外对照。
3. **氧化还原电位**——RX-392 存量 + N14 安全通道登记。
4. **ε（介电常数）**——**条件性激活**：ε 抽取模板是否激活，**取决于 W18-7 的结果**。

ε 分支写法（必须原样进入预注册）：

- **若 ε lane 冻结**（W18-7 判「封顶、无合法路径」）⇒ **ε 模板转档案**：本 §二 模板保留为历史规格，不投入 Week 20 规模化，也不占抽取预算。
- **若 ε lane 解冻 / 换线成功** ⇒ ε 通道按与 η **同一套字段模板**立项，另开预注册，不在本件内改口径。

该条件性在预注册里落为 `channel_priority.epsilon_template_activation = "deferred_to_w18_7"`；**本稿不单方判定 ε 通道的死活**。

## 四、Phase-0 方案

- **语料**：20–50 篇 **OA（开放获取）**论文。非 OA 一律转人工单篇复核流程（§七 红线 3），不进批量管线。
- **方法**：LLM + RAG 抽取，模板由本 §二 的字段清单驱动。
- **人工核对子集**：抽取结果的子集人工核对，作为 precision / recall 的金标准。子集大小与抽样方式**待作者确认**（建议 ≥ 20% 或 ≥ 50 条，取大者）。
- **阶段门**：先跑「模板稳定性」小样本（≤ 5 篇）；模板 v0 冻结后才放量，放量后不得改模板字段（改则重开预注册）。

## 五、建议门槛（**待作者确认，不得由本稿单方生效**）

| 门槛 | 建议值 | 作用域 | 不达标后果 |
| --- | --- | --- | --- |
| 数值字段 precision | ≥ 0.95 | `property_value` + `unit` + `temperature_K` | 整通道转人工复核，不得入库 |
| 数值字段 recall | ≥ 0.80 | 同上（金标准 = 人工核对子集） | 整通道转人工复核，不得入库 |
| 化合物消歧 precision | ≥ 0.90 | `compound_name → inchikey` | 全量记录转人工复核消歧 |
| DOI + 表/图定位完整率 | **= 100%（硬门）** | `source_doi` + `locator_table_figure` | **缺则不入库**（不是降级，是不入库） |

量级守卫（防单位/数量级错，同属建议值、同待确认）：η ∈ (0, 10] Pa·s（mPa·s 须先换算）；HOMO/LUMO ∈ [−15, 5] eV；氧化还原（vs Li/Li⁺）∈ [0, 10] V；ε ∈ [1, 300]。超界一律人工复核，不得静默入库。

**纪律**：上表四条门槛与量级守卫的全部数值均为建议；**作者未确认前不得作为验收判据，不得据此宣称任何通道达标，也不得据此宣称抽取路线成立**。

## 六、过门 / 不过门两条分支

- **过门（四条门槛全部达成）** ⇒ **Week 20 立项规模化**：语料扩到 200+ 篇 OA，按 §三 通道优先放量；每条记录仍必须带 DOI + 定位；入库前做 Reaxys 同源排除（与 §七 红线同构）。
- **不过门（任一门槛未达）** ⇒ **降级为半自动辅助工具**：LLM 只做「候选定位 + 预填字段」，**每条记录人核后才可能入库**；不硬上规模；半自动产物不得直接当训练数据。降级件仍受 §七 全部红线约束。

判据与分支必须在本预注册锁死之后才可执行抽取；**看到结果后再改门槛即违反 §W19-9**（lever-8 先例）。

## 七、红线（与 Reaxys 条款同构，已逐条写入预注册）

1. **图源读数与受限库值一律 `restricted_crosscheck_only`**：只作交叉核对，**永不入 `data/`、永不入任何池、永不入任何特征**。
2. **每条记录必须带 DOI + 表/图定位**；**无定位不入库**（硬门，见 §五）。
3. **出版商站点手动逐条查询合规；批量爬虫禁止**；OA API 除外，**且需登记**（登记项：API 名、许可条款、抓取时间窗、条数）。
4. **Reaxys 数值禁入池 / 特征 / 交付包**（§28.33 红线延续）：抽取值若与 Reaxys 同源同值，一律按 `restricted_crosscheck_only` 处置，不得因「文献里也印了同一个数」而洗白入库。

## 八、许可判读（计划 §W19-2 v2 新增）

- **EDB / ElectrolyteGPT 的字段设计可借鉴**：字段清单/表结构属思想与方法，不受版权保护；本模板 v0 是「抄字段设计、按四通道改造」的自研版本。
- **但其数据受 CC-BY-NC-ND 约束**：**不得改造后入库**。ND（NoDerivatives）禁止改造后再分发/入库；NC（NonCommercial）禁止商用。
- 结论：**只学字段设计，不取其数据**。`s43246` 的 RAG+LLM 流程同样按「方法可借鉴、数据不可搬运」处理：其 30% → 100% 是**流程证据**，不是可搬运语料。
