## 一、这一轮解决了什么

v0.3.6 的 tier-2 只按目标分子逐行读了 ECW-308 的 SI，留下两个口子：

1. **引文链断在数字上。** SI 的 "Refs." 列印的是方括号编号（`[3, 16]`），编号到完整文献的映射在同一份文件末尾的参考文献表里。只读目标页只能看到"Hall et al.; Flamme et al."这样无法核验的残片。
2. **没有全表交叉验证。** ECW-308 是本任务重叠度最高的免费汇编，逐行读只能验证 10 个目标，无法回答"数据集其余行是否也被这份汇编支持"。

本轮把 Table S3 的 308 行全部结构化，并把它与冻结数据集做了逐行对账。

## 二、方法：为什么必须做坐标抽取

纯文本 dump 无法支撑这次对账，实测原因是具体的：

- 行是**流式**排布的，多行挤在同一行（`... [16, 34, 36] 159. Propylene carbonate ...`）；
- 第 **279 行的行号在 PDF 里是一个裸 token `279`**，它后面的句点被 pypdf 单独成词（`279` `.` `1` `-` `Methyl` …）；
- 第 **167 行的行号与名称粘成一个 token**（`167.4-Trifluoromethyl...`）；
- SI 对部分条目**上下堆叠两个介电常数值**（MOPN：`36.00` 有引文、`25.00` 无引文）。

因此抽取走 pypdf 的坐标文本流，列归属完全由几何决定：

| 规则 | 内容 |
|---|---|
| 列带 | 介电常数列 = 粘度表头 x 与介电表头 x 的中点 → 介电表头 x 与电导表头 x 的中点（实测 486.3–559.7 pt） |
| 行号 | 行号必须等于**期望的下一个序号**（1→308）；无句点的裸整数**只对第 279 行**放行 |
| 行块 | 单元格归属于"基线在其正上方 0–20 pt（允许上溢 2 pt）"的那一行；名称/公式块则由**文档序上的下一行行标签**界定（跨页亦然） |
| 公式 | 只读取本行名下方、且**以下一行行标签为下界**的公式带；按印刷行逐行解析，第一个能构成合法化学式的行胜出 |
| 取值 | 只有带内恰好一个数值 token 才记 value，否则 blank / missing / stacked |
| 温度 | 列头写明 25 °C 且 SI 无逐行测温，故一律记 `temperature_source = column_header` |

**锚点回归：11/11。** v0.3.6 手工读出的 11 个值（EC 89.00、PC 64.90、VC 126.00、FEC 78.40、triglyme 7.53、diglyme 7.40、MOPN 36.00、ADN 30.00、GLN 37.00、sulfolane 43.00、ACN 37.00）在自动化结果中全部命中，且这 11 条已固化为**精确相等**的测试断言（不是"包含"断言）。

### 2.1 对抗审查发现并修复的两个抽取缺陷（v0.3.8）

首版抽取器通过了锚点回归，但只读对抗审查员用独立的 pypdf 扫描抓出两个 Critical 缺陷，均已修复：

| 缺陷 | 现象 | 修法 |
|---|---|---|
| 裸整数回退过宽 | 表头单词 `Category 1` 的 `1` 抢占了第 1 行（第 1 行实际丢失，被写成了 `Category 1`）；化学式下标 `3`/`4`/`9` 抢占了第 3/4/9 行 | 裸整数回退**钉死到第 279 行**（`BARE_INDEX_ROWS`），并补第 1/3/4/9 行的身份回归测试 |
| 公式窗口没有下界 | 固定 35 pt 窗口把**下一行的名称**拼进公式，导致 26 个有值的行公式解析失败、被误判为 `ecw_no_formula` | 公式窗口改以**下一行行标签为下界**；修正后无公式行从 26 降到 4 |

修正后第 1 行恢复为 `Formamide`（CH3NO），第 3/4/9 行恢复为 `Dimethyl acetamide` / `N-methylacetamide` / `Urea`，第 38 行恢复公式 `C2H3N`。**门控比较因此从 16 条增加到 24 条**（v0.3.8）。

### 2.2 第二轮对抗审查的三个缺口（v0.3.9）

第二轮只读审查没有再发现 Critical，但指出身份门控的三处**可证伪**缺口（下表）；这三条缺口同时暴露出四处抽取缺陷，见 §2.3。三者全部已修：

| 缺口 | 证据 | 修法 |
|---|---|---|
| 三条同物异名未进同义词表 | PubChem PUG-REST 同一 CID：`Butyl acetate` / `n-Butyl acetate` → CID 31272；`Acetone` / `Dimethyl ketone` → CID 180；`N-methylpyrrolidone` / `N-methylpyrrolidinone` → CID 13387 | 三条映射写入 `SYNONYM_NAMES`；三者由 `formula_only_candidate` 升为 ≤1% 一致 |
| 第 279 行名称带进了行号 | 先前报告写成"PDF 里没有句点"，实际 PDF 有句点，只是被 pypdf 拆成独立 token | 名称组装剥离"裸行号 + 紧随标点"；现为 `1 - Methyl - 2 - pyrrolidinone (NMP)` |
| `ecw_no_formula` 仍有 4 行 | 第 88/89 行是行距问题，第 43/116 行是跨页问题 | 见 §2.3；**该状态现为 0**（状态本身保留为安全网） |

### 2.3 抽取侧的四处根因修复（v0.3.9）

审查指出的缺口同时暴露出四处**抽取**缺陷；这些缺陷若只改计数就会被掩盖，因此按根因修：

| 缺陷 | 现象 | 修法 |
|---|---|---|
| 窗口上界太浅 | SI 有两种行距：多数页 24.6 pt，名称换行的页 48.7 pt。后者的公式落在行标签下方 **36.3 pt**，超出 35 pt 上界；第 88/89 行因此读不到公式 | 窗口上界放到 45 pt 并**逐行聚类**（同一行的元素符号与下标相差约 1 pt，行间距 ≥6 pt）；第 88/89 行恢复公式，另恢复 19 行 |
| 名称块被截断 | 名称换行时只读了标签所在的那一行（第 88 行读成 `1,1 - Difluoro 2 (2`） | 名称按**印刷行**拼接，直到公式行为止；续行必须起于名称列（x≤250），数值 token 不并入 |
| 跨页条目丢公式 | 第 43 行（MOPN）与第 116 行的公式印在**下一页最上方**，旧逻辑按页截断，读不到 | 块边界改用文档序 `(page, -y)`，跨页续写可读；两行均恢复公式 |
| 去重规则吃掉字符 | 旧规则"文本是已拼接串的子串就丢弃"把 `1`（在 `91.` 里）当成重复，`1-(2-Fluoroethoxy)-2-ethoxyethane` 丢掉两个位次号，`2-MeTHF` 丢掉 `Me` | 只有**同一坐标**的重复 token 才丢弃，重复的连字符与位次号一律保留 |

抽取修正的效果：**+21 行公式、112 个名称恢复被吞掉的字符、0 行回归**（对照 v0.3.8 的 JSON 逐行 diff，除公式/名称外无任何字段变化）。

## 五、全表对账：27 条通过身份门控的比较

身份门控 = **分子式一致 且 名称身份成立**（去括号全名相同，或命中显式同义词表）。只有分子式相同、名称身份不成立的行一律记 `formula_only_candidate`，**不计入冲突**。这条规则排除了甲酸甲酯↔乙酸、甲基丙基碳酸酯↔碳酸二乙酯这类假阳性。

**关键判读（本轮新增）**：三条腈类分歧**同一个根因**——它们全部只引 `[34]` Duncan 2013。上一轮对 Duncan 原文（NRC 接受稿）的核验已确认：该文 Table I 只印整数 `30 / 37 / 89`，**没有给出测量温度、频率与不确定度**，也不区分原始测量与比较数据。ECW-308 把这批整数抄成两位小数（`30.00 / 37.00`），精度是**二次汇编制造的**。

## 六、局限（不得越界使用）

1. ECW-308 是**二次汇编**，只能作为交叉核对与引文线索，不能覆盖数据集里的一手值。
2. 表头把数据来源写成"literatures and ChemSpider/PubChem database"，混合了文献值与数据库值；即使身份门控通过，仍需回读该行引文再引用。
3. 介电常数列统一标 25 °C，无逐行测温，**不能**据此推断数据集其他温度的记录。
4. 87/308 行有数值，204 行印 `/`（SI 本身无值），11 行单元格缺失，6 行堆叠——覆盖面有限，未被比较的行**不等于**"不一致"。
5. 19 行通过分子式但未通过身份门控，列为 `formula_only_candidate` 供人工判身份，**未**当作冲突。
6. 抽取器的行号序列自校验保证的是"序号 1..308 都出现在正确位置上"，它**不**保证 SI 本身印刷无误（例如本表已知的 `5.3.00` 黏度排版错误）。
