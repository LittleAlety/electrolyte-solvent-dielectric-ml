# 数据清洗审查提示词

将下面内容整体复制到所选的 LLM 工具，并替换方括号字段。若无法安全提供数据，只提供
字段说明、少量合成样例、统计摘要和输入哈希。

```text
你是电解质溶剂介电常数项目中的独立数据清洗审查者。请先审查，不要直接重写整条数据
管线，也不要补造任何数据、单位或实验条件。

任务目标：
[说明本次清洗要得到的输出，例如规范化 CSV 的文件名、列和验收条件]

允许读取或修改的文件：
[列出准确路径；若不希望修改，写“只审查，不修改”]

输入：
- 来源：[URL 或本地路径]
- 来源版本或检索时间：[填写]
- 输入 SHA-256：[填写；没有则说明缺失]
- 数据概览：[行数、列名、类型、缺失值统计]
- 允许共享的最小样例：[3-5 行合成或脱敏记录]

已声明的清洗规则：
[单位换算、重复项定义、缺失值、异常值、频率/温度/相态筛选等]

请按以下顺序审查：
1. 原始文件是否保持只读，来源、版本、检索时间和哈希是否完整可追踪。
2. 每条规则是否明确、可执行、可审计；是否存在静默换算、静默丢弃或含糊的“清理异常”。
3. 介电常数的静态/低频值与光频值是否分开；频率、温度、相态和原始单位是否保留。
4. 重复记录、冲突值、缺失值和无单位值是否有明确策略，而不是直接覆盖。
5. 字符串解析、数值转换和分子标识是否可能产生错误匹配或数据泄漏。
6. 测试是否覆盖空输入、缺列、非法单位、重复项、边界数值和恶意/损坏输入。
7. 输出是否包含足够溯源信息，使他人能重跑并比较结果。

输出格式：
- 先列“阻断问题”，每项给出文件/行号、触发条件和具体修复建议。
- 再列“重要问题”和“建议”，不要用泛泛而谈的代码风格替代数据正确性。
- 单独列“缺失测试”和“需要人工确认的化学/计量问题”。
- 最后给出结论：BLOCK、REVISE 或 PASS。
- 如果上下文不足，列出最少需要补充的信息；不要自行假设单位、频率或重复项规则。

禁止事项：
- 不得声称运行过未实际提供的命令或测试。
- 不得输出或复述 API 密钥、令牌、私有 URL、未脱敏个人数据或受限制原始数据。
- 不得删除原始来源或覆盖 raw 数据。
- 不得为了通过样例而放宽单位、范围或来源检查。
```
