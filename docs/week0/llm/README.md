# LLM 编程工作流

本流程与模型供应商无关。任何具备代码编辑、审查和可审计会话记录能力的 LLM 工具都可
接入；仓库不假设某一种聊天工具、IDE 插件或云端服务已经安装。工具只是执行者，最终
判断、数据责任和提交决定由人负责。

## 1. 小步任务拆分

每次只交给 LLM 一个可验收的小任务。开始前把以下内容写清楚：

1. 目标：要改变的可观察行为，而不是“优化一下”。
2. 范围：允许创建或修改的准确文件。
3. 输入输出契约：函数参数、命令参数、返回码、JSON 字段或数据列。
4. 验收标准：必须运行的测试和边界条件。
5. 非目标：本轮明确不做的重构、安装、联网或数据处理。
6. 交接条件：遇到缺失依赖、不明单位或需要密钥时停止并报告。

推荐顺序是“测试/验收标准 -> 最小实现 -> 审查 -> 修正 -> 再验证”。不要一次让 LLM
同时完成环境安装、数据下载、模型训练和论文写作。

## 2. 上下文最小化

只提供完成任务所需的接口、约束和最小样例：

- 优先提供文件路径、相关函数、数据模式和错误信息，不粘贴整个仓库。
- 数据只提供脱敏或合成的少量样例；字段名、单位和缺失值规则比大段原始记录更重要。
- 不粘贴 `.env`、API 密钥、访问令牌、Cookie、私有连接串或带签名的下载 URL。
- 日志和报错先删除用户名、主机名、令牌、私有路径及数据内容，再共享。
- 说明本机事实，例如“当前 PowerShell 没有 PATH 可用的 python/conda”，不要让模型
  猜测运行环境。
- 指定模型可看到的测试结果和允许使用的命令；禁止编造未运行的测试结果。

上下文清单建议固定为：任务目标、允许文件、接口契约、最小样例、验收命令、已知风险、
禁止事项。缺少关键信息时，先补充信息，不要让模型自行发明数据规则。

## 3. 代码审查门

任何 LLM 生成的代码在合并前都必须经过审查门。审查者可以是另一个会话，也可以由人
按同一清单执行，但不能只依赖代码作者自述“已经正确”。

审查顺序：

1. 正确性：实现是否满足验收标准，边界条件和失败路径是否处理。
2. 测试：测试是否先失败、是否覆盖缺包、旧版本、全通过等关键分支。
3. 数据科学正确性：单位、频率、温度、相态、重复项、缺失值和数据泄漏是否被保留或明确处理。
4. 可复现性：命令、依赖版本、随机种子、输入哈希、输出路径和提交版本是否可追踪。
5. 安全：是否读取或输出密钥、私有数据、未脱敏路径或不必要的外网请求。
6. 最小改动：是否修改了任务范围之外的文件，是否引入没有必要的依赖或抽象。

结论只能使用三种状态之一：`BLOCK`（存在必须修复的问题）、`REVISE`（需要修改后
复审）、`PASS`（允许进入下一验证步骤）。有未解释的失败测试时不得给出 `PASS`。

## 4. 数据与密钥安全

数据处理遵守以下硬规则：

- 原始 ThermoML 或其他来源文件只读，不覆盖、不静默截断、不丢失来源记录。
- 清洗结果必须保留来源 URL、检索时间、输入哈希、原始属性名、单位、温度、频率和相态。
- 单位换算、重复项合并和异常值删除必须有显式规则及可逆的审计记录。
- 对私有或受限制数据，只向外部模型提供合成样例、字段说明或脱敏摘要。
- 密钥只放在本机未跟踪的环境变量或本地配置中；文档和提示词只使用占位符。
- 提交前检查 diff、日志和 notebook 输出，防止密钥及原始敏感数据进入版本库。
- 不因 LLM 建议而启用未经审核的网络下载、遥测或数据上传。

## 5. 可复现实验记录

每次 LLM 辅助开发都保留一条精简记录，建议包含：

| 字段 | 内容 |
|---|---|
| task_id / 日期 | 稳定编号与本地日期 |
| 目标 | 本次要完成的行为 |
| 基线与提交 | Git commit 或工作区状态 |
| 输入 | 文件路径、数据版本、SHA-256；敏感内容只记哈希 |
| 提示词 | 使用的模板、版本和填写后的关键约束 |
| 工具 | 供应商无关描述；仅在可获知且有必要时记录模型/版本 |
| 命令 | 安装、检查、测试和复现命令 |
| 结果 | 退出码、测试数量、关键输出；不记录密钥或原始敏感数据 |
| 审查 | 审查者、`BLOCK/REVISE/PASS`、未决问题 |
| 下一步 | 人工决定与后续任务 |

记录目标是让别人能从相同输入、环境和命令重建同一结果，而不是复制完整聊天记录。

## 6. 提示词模板

两个可直接复制的模板：

- `prompts/data_cleaning_review.md`：审查数据清洗规则、异常处理和可追溯性。
- `prompts/code_review.md`：执行代码审查门并输出阻断问题、测试缺口和结论。

使用时替换所有方括号字段，只附上允许共享的最小上下文。模板中的“禁止”和输出格式
不要删除；它们负责限制模型猜测、越权修改和编造验证结果。
